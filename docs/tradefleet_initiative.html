TradeFleet: from methodology to a live fleet

The Agentic-Vibe-Fleet bet — that a constitution-first, agent-executed development method can ship real, governed software — has now been tested end-to-end on a real business initiative.

✓ THE INITIATIVE WORKS

Two production contractor sites live. One reusable template. ~$0/month each.

The initiative

The Director (a software developer) builds and hosts small-scale business websites for individual trade contractors — and trades that software skill for their trade skills: home upgrades, repairs, and maintenance. For the barter to make sense, every site has to be near-zero cost to run, fast to replicate, and self-serve for the contractor to operate (their own leads, jobs, invoices, schedule, and even the public site copy — no developer needed after handover).

Each contractor gets: a public promo site, a Google-sign-in admin workspace (Leads → Jobs → Invoices → Materials → Appointments → Email outbox), and a Site Content editor so the owner updates the public site with no redeploy. Stack: Vite + React + TypeScript · FastAPI · Firestore · Firebase Auth · Firebase Hosting (same-origin /api/** rewrite) · Cloud Run (scale-to-zero) — all inside free tiers.

How replication works

Mode 1 — new contractor: create a GitHub repo + Firebase project → fill the parameter table in TradeFleet/BOOTSTRAP.md (brand, owner, entity rename map, service names) → paste the prompt into a fresh agent session → clone, rebrand (case-sensitive, greppable placeholders), wire, gate, deploy. The template is a working app, so the agent validates each step against running code — not against hope.
Mode 2 — fleet rollout: build a feature in the template (or a child), then the rollout protocol ports the commit range to every repo in the Fleet Registry through that child’s entity/brand map, runs that child’s gates, and redeploys. Children deliberately diverge in naming, so rollout is agent-executed porting — the registry is what makes it mechanical.

What made it work (lessons now baked in)

  • Constitution-first beats tooling-first. Every session reads the architecture map and pattern registry before touching code; every commit is Bruno-gated. Drift never accumulated.
  • Contract tests made replication safe. 151 assertions re-run after every port proved the renamed twin behaved identically — including against real Firestore.
  • Production taught real lessons, now standing rules in the template: API responses must be Cache-Control: no-store (the hosting CDN cached 404s/401s and ignored Authorization in its cache key), .env values must be unquoted, singleton-document tests can wipe live data, hashed assets cache forever while index.html must not.
  • Editable content closes the loop. The contractor maintains their own site copy from the admin UI — the developer-free handover the barter model requires.
